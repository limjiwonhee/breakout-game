# 투자포트폴리오 관리 사이트

우리팀(투자사업팀)이 여러 계열법인 명의로 보유한 상장·비상장 대체투자 자산의 약정-납입-회수-밸류에이션을 한 곳에서 조회·기록하는 웹 사이트.

## 왜 만드나

- 문제 또는 동기: 현재 엑셀 한 파일(프로젝트목록 + 파생 현금흐름 시트 5개)로 관리 중인데, 파생 시트가 수동 재계산이라 어긋나기 쉽고(연도별 시트는 이미 `#REF!` 오류로 깨짐), 특정 날짜 기준 수익률(XIRR)이나 현황을 바로 확인하기 어려움.
- 배우려는 것 (이 차시에서 익힐 기술/개념): Next.js + Prisma + Supabase + Vercel 스택으로 실제 서비스를 처음부터 끝까지 만들어보는 경험.

## 무엇을 만드나

기능 단위로 하나씩 개발 승인을 받고 진행한다. 필수/선택 구분은 아래와 같다.

- 필수:
  - 로그인 (Supabase Auth), 마스터/관리자/뷰어 3단계 권한 — 마스터만 다른 팀원에게 관리자 권한을 부여·회수할 수 있음 (팀원 약 8~10명 예상)
  - 팀원 권한 관리 화면 (마스터 전용): 팀원 목록에서 관리자 권한 부여/회수
  - 전체 포트폴리오 대시보드: 기준일을 선택하면 그 시점까지의 총 약정액·누적투자액·누적회수액(원금/배당 구분)·미회수잔액·평가금액(NAV)·전체 수익률(XIRR, MOIC)을 표시. 투자법인별·투자유형별·국내외별 비중 차트 포함
  - 프로젝트(투자건) 리스트: 법인/유형/상태로 필터·정렬
  - 프로젝트 상세: 개요(사업명, 투자대상, 투자법인, 운용사, 지분율 등) + 캐시플로우 타임라인 + 해당 건의 XIRR/MOIC
  - 현금흐름 이벤트 입력: 납입/원금회수/배당수익을 날짜+금액+종류로 자유롭게 추가 (엑셀처럼 "몇 차 납입" 고정 칸이 아닌 이벤트 단위 — 임의 날짜 조회·XIRR 계산을 위해 필요)
  - 밸류에이션 이력 입력: 평가금액을 시점별 기록 (최신값 하나만이 아니라 히스토리로 관리)
  - 기존 엑셀 데이터 1회성 이관 (Claude가 엑셀을 분석해 시드 데이터로 변환)
  - 개발 환경 세팅 가이드 (부록): Node.js/Git은 이미 준비됨, GitHub·Supabase·Vercel 계정 가입 필요
  - 온보딩 화면: 첫 로그인 시 닫을 수 있는 팝업으로 간단 소개, 바로 닫고 대시보드로 넘어갈 수 있음
- 선택:
  - 상장 종목 실시간 시세/밸류 자동 조회 (직접투자·간접투자 포함)
  - 비상장 포트폴리오사 관련 최신 뉴스 자동 수집

## 만들지 않는다

- 실제 매매 체결이나 증권사 시스템 연동
- 세금 계산
- 모바일 전용 앱 (반응형 웹으로 대응)
- 엑셀 업로드/자동 파싱 기능 — 초기 이관은 Claude의 1회성 수동 변환으로 처리. 이후 팀원이 직접 엑셀을 올려 갱신하는 기능은 이번 범위 밖

## 화면과 흐름

1. 로그인 화면
2. 첫 로그인 시 온보딩 팝업 노출 (간단 소개, 언제든 닫기 가능) → 대시보드로 이동
3. 대시보드 (기본 진입 화면, 기준일 선택 가능)
4. 프로젝트 리스트
5. 프로젝트 상세 (캐시플로우/밸류에이션 조회·입력)
6. 신규 프로젝트 등록 (관리자 이상)
7. 팀원 권한 관리 (마스터 전용)

## 기술 스택

- 언어/프레임워크: Next.js, TypeScript, Prisma
- DB/인증: Supabase (Postgres + Auth)
- 배포: Vercel
- API/DB 상세 설계는 이 문서에서 다루지 않고 각 기능 개발 시점에 정한다.

## 성공 기준

- 정상 동작 (이 입력을 넣으면 이 결과가 나온다):
  - 임의의 과거 기준일을 선택하면, 그 시점까지의 누적투자액·누적회수액·XIRR이 원본 엑셀과 일치한다
  - 관리자가 새 납입/회수 이벤트나 밸류에이션을 입력하면 대시보드 수치에 즉시 반영된다
  - 뷰어 권한 계정은 모든 데이터를 조회할 수 있지만 입력·수정은 할 수 없다
  - 마스터 계정만 다른 팀원의 관리자 권한을 부여·회수할 수 있다
- 절대 하면 안 되는 것:
  - 뷰어 권한으로 데이터를 수정할 수 있는 경우
  - 마스터가 아닌 계정이 다른 사람의 권한을 바꿀 수 있는 경우
  - 현금흐름 입력 과정에서 기존 원본 데이터(엑셀 이관분)가 유실되는 경우
